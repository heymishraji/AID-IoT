# AID UI Previews (identity round 1)

`index.html` has two tabs: **What we learned** (ten lessons from the 51 reference brands, plus a table of all
references) and **Previews** (suggestive screens for both brands: AID IoT landing, product page and Signal
dashboard; AID Defence landing, Lighthouse page and Lighthouse console).

The previews are built with the brand library itself, not a copy:
- `css/tokens.css` → `packages/brand-library/dist/all.css` (run `npm run build` first; `dist/` is generated)
- `css/components.css` → `packages/brand-library/core/components/components.css`
- `css/routes.css` → `routes.css`, generated by `routes.py`: each colour route overrides only the brand roles and the
  neutral scale; semantic tokens, status, focus, classification, symbology and night mode stay the library's.
- `img/` → the generated mood images in `assets/imagery/generated/`
- `logo/logo-kit.js` → `docs/studies/logo-modernisation/logo-kit.js` (the modernised current mark; the page falls
  back to the current mark in one colour if it is missing)
These are symlinks for local viewing. The published artifact maps the same paths to the same sources.

Every screen works in light, dark and night mode, and the Compare view shows all three colour routes side by side.
Finding to carry forward: route neutrals are brand-specific (warm grey for AID IoT, slate/graphite/basalt for AID
Defence), but the library currently treats neutrals as core-owned. If a route with tinted neutrals wins, brands
need a `brand.neutral` role (a library change to decide then).
